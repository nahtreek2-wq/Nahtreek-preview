# Preview UI, signup and notification fixes

## Delivered

- Client registration omits empty personal-profile fields until onboarding. The old payload failed `RegisterDto` validation; 400/422 validation messages now reach the UI. Old success instructions clear when an operation fails.
- Client authentication requests have their own 45-second response window rather than the ordinary write timeout. Account creation now creates the refresh session within the same database transaction as the verified user, avoiding the previous final database round trip and preventing a verified account without a session when that round trip fails.
- Client account and AI-planner forms now move their lower fields above the Android keyboard; internal screen headers have a compact NAHTREEK logo/name line; Find uses a location-neutral heading; and Profile has a larger identity area with clearer home, activity, preference and support sections.
- The shared app navy was updated to a darker logo-aligned colour, the splash logo is larger, and AI recommendation rows now use neutral cards instead of unnecessary yellow fills.
- A follow-up sampled the logo image directly: its dominant background is `#111F35`. The Client splash, login header, primary navy tokens, Android launch background and system bars now use that exact representative colour.
- The guest AI page uses a scrollable layout with explicit spacing. A 320×640 emulator accessibility layout showed the description ending at y=453 and the button starting at y=469.
- Professional profile, verification, editing, chat, notifications and request headers account for the top safe area. Home shows the official logo and Today at a glance before promotional content. Bottom navigation follows the client's rounded style; secondary home icons are neutral.
- Public profile uses real specialization labels, completed-job counts, ratings and uploaded portfolio photos instead of stock work images. Add a title and use **Add work photo**. Only the owner may remove a portfolio listing. Images are public; identity documents are not.
- Approved verification displays **Profile verified**. Rejected proofs do not satisfy submission. The professional status list no longer requests signed storage URLs for files it does not display.
- Preview push delivery is enabled. A Vault-protected Supabase minute job dispatches pending rows. The requested test was accepted by FCM on its first attempt. The database-to-Vercel dispatcher returned 201 with delivery enabled.

## Verification and remaining acceptance

- Client: 50 tests passed. Professionals: 8 tests passed. API: 85 unit tests passed. Both mobile apps and API passed TypeScript checks. Both internal APK builds passed.
- The first full isolated database journey had intermittent 500 responses. A focused service-provider journey, including photo upload/ownership, verification, exact booking, chat and completion, passed.
- Fresh focused service-provider and engineer journeys both passed after the pool configuration correction. Each covers verification, exact booking, chat, completion and history; the engineer path completed in 55 seconds.
- A later full rerun encountered Prisma `P1017` (server closed connection) during chat creation. Its prolonged runtime also expired a test access token. This is not evidence that live database/network reliability is solved. Do not automatically retry uncertain writes.
- The preview API keeps the configured Supabase session pooler and limits each serverless instance to one Prisma connection, after a transaction-pooler test added unacceptable multi-second delays. It has bounded connection and transaction waits and maps transient Prisma connection failures to a clear 503 response. Read-only app queries retry once; writes deliberately do not retry automatically, so a booking cannot be duplicated after an uncertain response. The deployed preview health endpoint returned 200 after this configuration was published.
- The user still needs to confirm notification display on the physical phone and test signup and portfolio upload in the new APKs. The integration harness mocks external mail/storage transport; it does not prove Gmail or real image storage delivery.
- Promotional campaigns, per-event notification wording, request deep links and production Firebase remain future work. Minute polling is not an instant-delivery guarantee; ten rows are processed per batch.
- Portfolio listing removal does not delete the underlying storage object. Retention cleanup and a complete provider-facing/client-facing gallery review remain follow-up work.
- No claim that every screen/device is polished or that the application is production-ready. Kluster tools were unavailable.
